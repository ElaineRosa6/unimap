## 1. 目标与范围

本计划以当前已经通过的 API 查询、Bridge 主链路、普通网页 CDP headless 截图、调度、
通知、持久化和云端容器基线为起点，完成以下工作：

1. 完成五个稳定 Web 引擎的真实 CDP 能力定级；
2. 建立 Cookie/Profile 无人值守探测、熔断、告警和恢复闭环；
3. 将 Censys、DayDayMap 从 API-only 扩展到稳定 Web UI、Bridge 和 CDP；
4. 补齐配额、历史筛选、只读配置提示和受控恢复能力；
5. 完成 ARM64、TLS、容量、恢复和持续运行验收；
6. 同步 API、Runbook、架构、变更日志和日期化验收证据。

本计划假定 Censys、DayDayMap 采用“完整浏览器支持”路线，而不是长期保持 API-only。

## 2. 排期基准

- 以一名主开发者持续投入为估算基准；
- 每旬约 10 天，包含开发、测试、真实联调、修复和文档；
- 真实引擎验收要求用户及时提供合法账号、Cookie、API Key、低额度查询和验证码配合；
- 每阶段必须先通过受影响包测试，再通过全量 race、vet、build 和必要的 GUI/浏览器测试；
- 登录页、验证码页、空结果页或普通网页截图不能作为结构化采集通过证据；
- 前一阶段存在 P0/P1 回归时，不进入下一阶段扩展范围。

当前阶段在以下关系中采取的平衡点：

| 关系 | 当前侧重 | 最低保障 |
|---|---|---|
| 速度与质量 | 质量 | 每旬保留回归和真实验收时间 |
| 新引擎与稳定引擎 | 稳定引擎 | 五引擎 CDP 定级完成后再扩展 |
| API 与浏览器能力 | API 保底、浏览器增强 | 浏览器失败不得影响 API 查询 |
| 功能与运维 | 先形成业务闭环 | 12 月前完成恢复和持续运行验收 |

## 4. 分阶段实施

### P0：基线收口（2026 年 7 月下旬）

实施内容：

- 审查当前工作区变更，确认用户文件不被覆盖；
- 处理可能导致 `go run .` 意外启动 Chrome 的临时入口；
- 固定当前引擎能力矩阵和发布基线；
- 执行全量 race、vet、build、GUI build 和前端语法检查；
- 整理变更日志、待办和发布前检查记录。

验收门槛：

- 默认测试不启动 Chrome；
- 全量验证通过且无新增 P0/P1 问题；
- 文档对 Censys、DayDayMap、Bridge、CDP 的描述与代码一致。

### P1：Quake、Hunter 真实 CDP 闭环（2026 年 8 月上旬）

实施内容：

- 分别验证 API 最小查询与配额行为；
- 导入并验证 Web Cookie；
- 使用云端 headless CDP 打开真实搜索结果页；
- 修复 Network/DOM 提取、登录墙和验证码识别；
- 验证结构化资产、PNG、SQLite、通知和重启恢复。

验收门槛：

- 每个引擎均产生非空且字段合理的结构化资产；
- 截图经人工确认不是登录页、验证码页或错误页；
- `collect_and_capture` 的查询、入库、截图和通知结果一致；
- 容器重启后 Profile、历史和截图仍可用。

### P2：五个稳定引擎 CDP 定级（2026 年 8 月中旬至下旬）

实施内容：

- 8 月中旬完成 FOFA、ZoomEye、Shodan 实测和适配修复；
- 8 月下旬完成 FOFA、Hunter、ZoomEye、Quake、Shodan 的统一 Live E2E；
- 为登录墙、验证码、选择器变化、网络失败和空资产定义稳定错误码；
- 输出逐引擎“通过、受限或不支持”的能力结论。

验收门槛：

- 五个引擎均有日期化真实证据，不以单元测试代替；
- CDP 失败时 API 主链路仍然可用；
- 页面异常不会被报告为采集成功；
- 全量回归通过。

### P3：Cookie/Profile 无人值守闭环（2026 年 9 月上旬至下旬）

实施内容：

- 9 月上旬：增加周期性真实结果页登录探针和状态存储；
- 9 月中旬：增加连续失败熔断、任务暂停、通知和恢复操作；
- 9 月下旬：更新 Cookie 后自动执行低额度查询、截图、入库和通知复验；
- 记录最后成功时间、失败分类和建议恢复步骤。

验收门槛：

- 能区分 Cookie 缺失、过期、登录墙、验证码、页面变化和网络失败；
- 连续失败后停止消耗浏览器任务，不产生成功误报；
- 会话恢复后可自动解除熔断并形成审计记录；
- 完成至少 24 小时无人值守观察。

### P4：Censys、DayDayMap 完整接入（2026 年 10 月上旬至 11 月上旬）

实施内容：

- 10 月上旬：接入稳定 Web UI、设置页、查询选择、结果展示和导出；
- 10 月中旬：补齐搜索 URL、UQL Web 翻译、Cookie、登录态和 Bridge `ExtractJS`；
- 10 月下旬：实现 CDP Network/DOM 结构化采集、截图、调度和通知；
- 11 月上旬：完成两个引擎 API、Bridge、CDP 的真实联调和回归。

验收门槛：

- 前端只展示当前真正可执行的能力；
- API、Bridge、CDP 分别记录独立测试结果；
- 缺少凭据时不注册伪可用 Web-only adapter；
- 两个引擎均完成查询、资产、截图、入库和通知闭环，或明确记录受限结论。

### P5：产品与运维收尾（2026 年 11 月中旬至下旬）

11 月中旬：

- 增加配额历史存储、趋势图和自动刷新设置；
- 将现有 `quota_monitor` 与可配置阈值、通知和 UI 状态打通；
- 明确无配额接口引擎的展示语义。

11 月下旬：

- ~~历史 API 增加 `start_time`、`end_time`；~~ 已于 2026-07-24 提前完成；
- 不可写配置模式显示明确提示并禁用保存；
- 提供受控恢复命令或管理 API，包含校验、备份点和失败回滚；
- 定义配额、截图、巡检和日志保留策略。

验收门槛：

- 配额页面不再使用占位或伪实时数据；
- readonly 用户和不可写配置不会出现“可保存但必然失败”的交互；
- 恢复操作不会覆盖当前数据而缺少回滚点；
- API、Runbook 和前端契约同步更新。

### P6：生产化验收（2026 年 12 月上旬至下旬）

实施内容：

- 12 月上旬：构建并验证 ARM64 镜像及 Chromium；
- 12 月上旬：配置域名、TLS、反向代理、安全组和日志轮转；
- 12 月中旬：执行代表性并发、资源上限、备份和隔离恢复演练；
- 12 月中旬：完成至少 24 小时持续运行观察；
- 12 月下旬：全量回归、发布、回滚演练和最终文档收口。

验收门槛：

- 只有设计允许的端口对外开放，CDP 和 Bridge 不暴露公网；
- 无 OOM、持续进程泄漏、失控磁盘增长和任务永久卡住；
- 异机备份与隔离恢复成功；
- readiness、任务失败、登录失效和备份失败均能告警；
- 发布和回滚步骤由 Runbook 实际走通。

## 6. 延期与调整规则

- 账号、Cookie、验证码或测试额度未按期具备：对应真实验收顺延一旬，非账号依赖工作继续；
- 任一阶段发现 P0/P1 回归：暂停下一阶段，先修复并重新执行当前阶段验收；
- 9 月下旬仍未形成稳定会话闭环：暂停 Censys、DayDayMap 浏览器扩展，优先修复会话系统；
- Censys 或 DayDayMap 明确禁止或无法稳定自动化：记录为 API-only，不使用脆弱绕过方案；
- 服务器容量低于实际负载：仅给出轻量试运行结论，不标记生产容量通过；
- 每旬末复核一次排期；累计偏差超过一旬时更新本文并记录原因。
